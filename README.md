# 小球大战 Ball Battle

参考 Orbitlity「64 小球锦标赛」视频（B 站合集，视频本身不在仓库里）复刻的自动对战小游戏：两个小球在方形竞技场里不停反弹，各自靠特殊能力打掉对方的 100 点血。

技术栈：React 19 + Vite + Tailwind CSS v4 + TypeScript，画面用 Canvas 2D 绘制，音效由 WebAudio 实时合成（没有任何素材文件）。联机部分跑在 Cloudflare 上：Workers（Hono）+ Durable Objects + D1。

## 运行

```bash
bun install
bun run db:migrate:local   # 第一次运行前：建本地 D1 表
bun run dev        # 开发服务器（前端 + Worker/Durable Objects/D1 一起在本地跑）
bun run build      # 类型检查 + 生产构建（dist/client 前端，dist/ball_battle Worker）
bun run deploy     # 构建 → 应用远程 D1 迁移 → 部署到 Cloudflare（https://ball.contextudio.com）
bun run sim 100    # 无头模拟：每组对局各打 100×2 局，输出胜率和时长
bun run dps        # 各角色在不同时间段的每秒伤害
bun run vsall knight,hive 10   # 指定角色对全体的胜率（调参时用）
bun run check:determinism      # 全部 3003 组对局在 JavaScriptCore / V8 下必须逐位一致（联机的前提）
bun run check:dmath            # 确定性数学库对照原生 Math 的精度测试
bun run check:i18n             # 中英文文案的插值参数一致、角色规则用到的数值都有来源
bun run typegen    # 改了 wrangler.jsonc 之后重新生成 worker-configuration.d.ts
```

## 联机对战

两种模式，游客（取个昵称）和登录用户都能玩：

- **A · 暗选单局**：双方同时秘密选角，都锁定后同时亮出，一局定胜负。
- **B · 三局两胜**：首局暗选；之后胜者保留角色，败者可以换角色针对（平局则双方重新暗选）。

每次选角限时 45 秒，超时自动锁定当前选中的角色（没选就随机）。系列赛进行中离开房间、或断线超过 60 秒判负。登录 GitHub / Google 后可以保留战绩、用好友码加好友、看到好友是否在线并直接发邀请；游客登录时，原来的昵称和战绩会跟着转到账号上。

### 为什么几乎不耗服务器资源

对局不需要同步每一帧：一局完全由「左右角色 + 种子」决定，服务器只负责收发选角、发一个种子和统一的开始时间（`startAt`），每个浏览器按校准过的服务器时钟在本地把同一场对局放出来。服务器自己也无头跑一遍当裁判（每局约 3 ms CPU），用来记分和写战绩。对局期间房间的 Durable Object 处于 WebSocket 休眠状态，不占运行时长。

前提是模拟在所有 JS 引擎里逐位一致。ECMAScript 允许 `Math.sin/cos/atan2/hypot/exp/pow…` 和 `**` 在不同引擎里有最后一位的差异，混沌的弹球模拟会把它放大成不同的胜负（实测改造前 400 局里有 5 局 JavaScriptCore 和 V8 的胜者不同）。所以模拟代码统一用 `src/game/core/dmath.ts`（移植自 musl/fdlibm，只用 IEEE 754 的加减乘除和开方），平方用 `sq()`/`cube()`。`.oxlintrc.json` 在 `engine/`、`characters/`、`core/` 里禁用了这些原生函数、`**` 和 `Math.random`（`lint/determinism.js` 是对应的本地规则），`bun run check:determinism` 负责验证。

### 部署前的一次性配置

1. 创建 D1 数据库，把输出的 `database_id` 填进 `wrangler.jsonc`：
   ```bash
   bunx wrangler d1 create ball-battle
   ```
2. 创建 OAuth 应用（只配其中一个也可以，没配置的登录方式不会显示）：
   - GitHub：Settings → Developer settings → OAuth Apps，Callback URL 填 `https://ball.contextudio.com/api/auth/github/callback`
   - Google：Google Cloud Console → APIs & Services → Credentials → OAuth client ID（Web），Authorized redirect URI 填 `https://ball.contextudio.com/api/auth/google/callback`
3. 把密钥存成 Worker secrets：
   ```bash
   bunx wrangler secret put GITHUB_CLIENT_ID
   bunx wrangler secret put GITHUB_CLIENT_SECRET
   bunx wrangler secret put GOOGLE_CLIENT_ID
   bunx wrangler secret put GOOGLE_CLIENT_SECRET
   ```
   本地开发用的话，复制 `.dev.vars.example` 为 `.dev.vars` 填上（回调地址换成 `http://localhost:5173/...`，需要单独建一个开发用的 OAuth 应用）。
4. `bun run deploy`。

## 多语言

界面支持中文和英文（i18next + react-i18next），右上角切换，选择会记在 localStorage；第一次访问按浏览器语言自动选择（zh-* → 中文，其他 → 英文）。

- 文案在 `src/i18n/locales/<语言>/`：`common.ts` 是界面文字，`characters.ts` 是角色名、简介和规则。中文是源语言，其他语言用 `LocaleShape<typeof zh>` 约束，缺 key 或数组长度不一致会直接编译报错；`t()` 的插值参数也有类型检查。
- 角色规则里的数字不写死在文案里：文案用 `{{hammerDamage}}` 这样的占位符，角色定义里的 `ruleValues` 把对应的调参常量传进去，所以改了数值，两种语言的说明都会同步。`bun run check:i18n` 会检查占位符和 `ruleValues` 一一对应。
- 服务器只返回错误代码（`{ error: 'room_not_found' }`），由前端按当前语言显示；新增错误代码时在 `src/net/apiTypes.ts` 的 `ApiErrorCode` 里加上，中文文案缺了会编译报错。
- 加一种新语言：在 `locales/` 下新建目录，照中文的结构写 `common.ts` / `characters.ts`，再加进 `src/i18n/resources.ts`。

### 和原视频不一致的地方（有意为之）

- **列车长**：原作里火车能把敌人一路拖着碾（实测单班最高约 -60），模拟里出现过单班 -150 的情况。改为每班车最多命中 3 次，同时让下一条铁轨提前开铺，用稳定输出代替一击秒杀。
- **船锚**：原作只有甩动，命中率太低；加了「抛竿 + 回拽」。
- **手榴弹**：原作看起来没有瞄准，但按原作的伤害反推命中率约 35%，随机散布只有 5%，所以改为带提前量的抛掷。
- **象棋**：原作随机抽棋子、整个棋盘阶段无敌；这里改为挑最合适的棋子、只在冲刺阶段无敌，避免对局拖进加时。
- **激光 V2 / V3、强酸**：原作的线、炮台、酸液都没有上限，在我们的场地比例下会铺满全场，所以都加了数量上限；强酸的腐蚀改为挂在敌人身上的状态（多滩叠加最多 2 倍）。
- **五条悟**：原作每隔 5 秒出现的圆环没有任何可观察的效果，没有实现。
- **黑洞**：只实现了 V1；V2 的伤害和引力规则从视频里无法确定。
- **召唤物**（复制者的分身、死灵巫师的骷髅、蜂巢的蜜蜂等）：引擎里只有两个球能被攻击，所以召唤物都不可被攻击，改为有存活时间。
- **骑士**：原作举盾期间完全免疫，保留；但举盾时间缩短为 1.5~3 秒（持剑 2~8 秒）、剑伤 -10 → -6、剑长 4.6R → 3.8R，否则胜率高达 95%。
- **模仿者**：每次变身都会重置所借能力的冷却和成长，平均只能发挥原角色约 65% 的输出，所以变身期间伤害 ×1.5（引擎的「输出伤害倍率」钩子，余数会结转到下一击，小伤害也能按比例加成）。
- **铁刺**：原作自己碰到钢刺和敌人一样掉血，按原规则胜率只有 3%；改为自己碰到只 -1，敌人 -5。
- **大炮、星陨**：原作看起来是瞄准当前位置，但炮弹/陨石很慢，几乎打不中移动目标；改为按敌人的反弹路线预判瞄准。
- **电钻**：原作钻完后电钻会向后弹开，按这个规则贴身型角色（吸血鬼、病毒、雷电……）几乎永远碰不到电钻，胜率是 0%。改为钻的时候两球锁在一起、钻完各自恢复原来的运动方向：原本相向而来的两球会撞上，这时电钻还在冷却，贴身角色可以反击。冷却相应缩短为 1.6 秒。
- **蜘蛛**：原作被网住的敌人头顶有缴械图标，按「网住期间缴械」实现（之前的版本里被网住的敌人照样能出招，蜘蛛胜率垫底、对 21 个角色低于 20%）。
- **缴械的统一规则**：缴械期间不能发起新的攻击，已经放出去的东西（飞行中的弹体、地上的陷阱、已召唤的小兵）照样有效；拿在手里/绕身转的武器（铁锯、刺客、骑士、锤神、回旋镖）不伤人。病毒的接触传染是它的设定，不受缴械影响。
- **其余角色**：机制按视频还原，伤害/间隔等数值为了平衡做过调整（见下文）。

视频里出现过的角色已经全部实现。

## 操作（本地观战）

- `空格` 暂停 / 继续 · `1`–`4` 切换 0.5x / 1x / 2x / 4x 速度
- `R` 用同一个种子重播 · `N` 换新种子再战 · `M` 静音 · `Esc` 返回选角

模拟使用固定步长（120Hz）和可设定种子的随机数，所以相同的角色 + 种子必定得到完全相同的对局。

新增角色：在 `characters/` 里继承 `Ability`，按需实现 `onWallBounce` / `onBallContact` / `update` 和对应的 `render*` 钩子，再到 `registry.ts` 注册，并在 `engine/types.ts` 的 `CharacterId` 里加上 id；名字、简介和规则写进 `src/i18n/locales/*/characters.ts`，规则里引用的数值放进定义的 `ruleValues`。如果有新的伤害类型，在 `DamageKind` 里加上它，并在 `engine/hitEffects.ts` 里配好命中特效和音效。发动新攻击前要检查 `owner.disarmed`（锤神的缴械），否则缴械对它不起作用。

## 平衡性

`bun run sim 16` 会把所有组合（77 个角色，2926 组）各打 32 局。目前所有角色的总胜率都在 41%–59% 之间，对局时长中位数约 37 秒（10%–90% 分位 26–53 秒），与原视频接近。`bun run dps 6 角色id,角色id` 可以只测指定角色的输出曲线，`bun run vsall 角色id 10` 可以快速看单个角色调参后的胜率。

只靠身体碰撞输出的角色（铁锯 V2、病毒、仙人掌等）天生碰撞频率低，所以单次伤害给得比较高；叠层/成长型角色（毒刺、蜘蛛网、长矛、激光 V3）前期弱、后期强，这是角色特色。

有几组是机制上的硬克制，属于角色定位，没有特殊处理：

- **锤神 克制 吸血鬼**：吸血鬼要贴身才能咬，而旋转的锤子会持续惩罚靠近，被砸中还会缴械。
- **电钻 克制 青蛙**：青蛙要把猎物拖到嘴边，等于把电钻送到自己脸上。
- **吸血鬼 克制 雷电**：被咬住后两球连在一起，不会再发生新的碰撞，雷电没法再次放电。
- **蜘蛛 克制 毒刺、列车长**：这两个角色靠撞墙发动能力，被定身时什么都做不了。
- **窃贼**：去掉了「偷来的能力伤害 ×0.6」——引擎规定每下至少 1 点伤害，所以这个倍率对每下只打 1 点的能力（蛛网、弓箭手、时停飞刀……）根本不起作用，改为缩短偷来能力的持续时间来平衡。最初设计是「被偷的敌人缴械到窃贼把能力用完为止」，模拟下来极度两极（拿武器的角色全程无力，放陷阱的角色毫无损失），所以缴械缩短为 2 秒，偷同一个角色可以续时间、保留它已经放出的陷阱。
- **镜子**：反射的伤害在镜子自己的下一步结算，而不是在受伤的那一刻立刻打回去，避免打断攻击方正在进行的结算（例如分裂球正在遍历碎片）。
- **鱼钩**：甩钩时靠把自己的速度降到 0 来站定，而不是把自己固定住（`pinned`）——固定的球会免疫所有抓取，之前导致鱼钩甩钩时谁都钩不动它（包括窃贼偷来的鱼钩、另一个鱼钩）。两次甩钩之间间隔 5 秒，避免对手一直被钩着；即便如此，象棋（冲刺无敌）、火山（喷发时固定在原地）、流沙、蜘蛛对它仍然很强。
- **蜘蛛 互相网住**：两只蜘蛛同时网住对方时，以前谁都爬不过去，只能干等到加时；现在被定住的蜘蛛会用蛛丝把猎物拉过来，互相拉到一起再互咬。
